## 3. Bước 3 — Resolve physical location và enforce root policy

### 3.1 Physical code location

- Trả **canonical path trên default/native filesystem** tới exploded classes directory hoặc **outer physical JAR file**. Không chấp nhận ZipPath/entry path là physical location. Kiểm tra filesystem/provider rõ để không im lặng so `startsWith` giữa hai providers.
- Hỗ trợ CodeSource `file:` của exploded classes/plain JAR và Boot `jar:nested:...!/` của version đang dùng. Nếu thêm hỗ trợ standard `jar:file:...!/`, unit-test resolver rõ. Dùng URI/URL connection hoặc API phù hợp để lấy outer artifact; đọc documentation/source chính thức khi cần.
- Windows drive, path có spaces/percent encoding và Unicode phải round-trip đúng. Không lấy substring tùy tiện làm mất drive/root, replace mọi `!`/`%20`, dùng URLDecoder theo form semantics hoặc hard-code path máy reviewer. Không dùng user.dir/working directory làm vị trí app.
- Unsupported scheme, code location thiếu/không tồn tại/non-native/ambiguous phải fail closed bằng diagnostic an toàn. Không fallback cwd/temp/public hay nhận root để ứng dụng khởi động. Preserve cause ở tầng nội bộ theo quy ước nhưng không raw log path/locator/secret hoặc lộ qua HTTP.
- Không thêm dependency hay nâng Boot/JDK chỉ để né CodeSource hiện có nếu API đang có đủ dùng. Storage disabled vẫn hoạt động đúng hợp đồng, không tạo root hoặc đòi cấu hình root không cần thiết.

### 3.2 Protected roots

- Derive từ **physical** artifact/location. Giữ bảo vệ JAR parent, classes location và nearest project/repository roots theo policy đã có. Root dự án có `pom.xml`/build descriptor hoặc Git metadata phải bảo vệ toàn cây, kể cả `config`, `public`, `target`, folder tùy tên.
- Existing absolute directory, canonical containment, no symlink root và writable checks giữ. Cùng filesystem mới được so containment; không dựa vào tên hiển thị `/` để kết luận. Root trong app/repo phải bị reject trước file write.
- Valid external root thực sự ngoài app/repository phải accepted dù app được launch từ CWD khác; không cấm mọi AppData/TEMP hoặc cả ổ đĩa vì CWD/ancestor không liên quan. Với standalone JAR, ghi rõ boundary artifact parent được bảo vệ.
- Read/delete locator checks, UUID receipt ownership và authenticated file access giữ nguyên. Không sửa configuration bằng cách chuyển private root vào repo rồi nới guard.
