## 2. R1 — Cấu hình local phải ở ngoài artifact

Hiện `docs/LOCAL_DEVELOPMENT.md` hướng dẫn copy example thành `src/main/resources/application-local.properties`. Pom đóng gói file đó vào `BOOT-INF/classes/application-local.properties`; Git ignore không loại file khỏi JAR. Reviewer đã chứng minh bằng một marker giả.

Yêu cầu sửa:

1. Chuyển cách dùng local config sang file ngoài classpath, đề xuất `<repo>/config/application-local.properties`. Dùng profile `local` và cấu hình Spring Boot phù hợp; ghi rõ phải chạy từ root hoặc chỉ định vị trí config ngoài khi chạy nơi khác.
2. Đặt example ở vị trí có nghĩa và cập nhật chỉ dẫn copy/run. Example có thể được chuyển sang `config/application-local.properties.example`; tránh để hai hướng dẫn mâu thuẫn. Không tạo local file chứa secret thật.
3. Giữ file local thật bị Git ignore, example vẫn theo dõi được. Không đưa toàn bộ config directory vào ignore khiến mẫu cũng biến mất.
4. Thêm bảo vệ trong cấu hình build để `application-local.properties` thật không lọt vào resources/JAR nếu bị đặt nhầm trong src/main/resources. Chỉ loại các file local/secret thích hợp; giữ application.properties và tài nguyên hợp lệ.
5. Kiểm tra profile local ngoài JAR thực sự được nạp bằng một giá trị vô hại, ví dụ override Clock zone hoặc cấu hình tương đương. Health đơn thuần trả 200 chưa chứng minh file đã được đọc.
6. Kiểm tra artifact với một bản sao hoặc fixture tạm có marker giả trong local file ở vị trí từng gây lỗi. Sau clean package/verify, mở JAR và chứng minh không có file/local marker đó. Chỉ quét JAR thiếu fixture giả thì chưa chứng minh exclude có tác dụng.
7. Ghi một test hoặc script kiểm tra tái lập được cho bước đóng gói. Không tự động khởi chạy Maven lồng vào mỗi unit test; có thể dùng script PowerShell riêng được tài liệu hóa. Script phải bảo toàn file local sẵn có, dùng dữ liệu giả và cô lập thư mục tạm.

Không đọc/in credential thật. Không overwrite local properties của người dùng nếu đã tồn tại. Khi dọn thư mục tạm, xác minh đường dẫn tuyệt đối nằm trong vị trí do script tạo; chỉ dừng process do script khởi tạo.

Nguồn chính thức nếu cần: Maven Resources includes/excludes và Spring Boot Externalized Configuration, liên kết trong báo cáo review.

## 3. R2 — Không trả defaultMessage thô của binding failure

Hiện `GlobalExceptionHandler.toFieldError` trả thẳng `FieldError.getDefaultMessage()`. Với Integer field qua form binding, message chứa nguyên rejected value và kiểu Java.

Yêu cầu sửa:

1. Phân biệt binding/type-conversion failure với thông báo Bean Validation do ứng dụng kiểm soát.
2. Lỗi binding trả thông điệp an toàn có nghĩa, ví dụ “Giá trị không hợp lệ” hoặc thông điệp theo error code đã kiểm soát. Không đưa raw exception/defaultMessage/rejectedValue vào response.
3. Giữ message validation an toàn đang có, ví dụ `@Size` trong fixture hiện tại. Nếu bổ sung cơ chế dịch lỗi, dùng cơ chế nhỏ và rõ; không dựng framework message phức tạp.
4. Không chữa bằng replace đúng chuỗi marker, hoặc loại field lỗi khỏi response để test qua.
5. Thêm regression test HTTP với fixture chỉ trong `src/test`: `@Valid @ModelAttribute` có field Integer, gửi form-urlencoded với giá trị sai dạng và marker giả.
6. Assert response vẫn 400, code VALIDATION_ERROR, có tên field đúng, message an toàn, traceId khớp X-Request-ID; không chứa marker, giá trị bị từ chối hoặc chuỗi chẩn đoán kiểu `java.lang.*`/`Failed to convert property value`.
7. Giữ các kiểm tra JSON validation, malformed JSON, AppException, 500, 404/405/415, Clock và trace/MDC đang đạt. Nếu thay đổi test, giải thích lý do; không nới assertion che lỗi.

## 4. Kiểm tra bắt buộc và bằng chứng

- Chạy `.\mvnw.cmd -B clean verify`, JAVA_HOME chỉ đặt ở tiến trình nếu cần.
- Ghi số test thực tế và kết quả; phân biệt test tự động với probe/script đóng gói.
- Chạy regression R2 với form marker giả.
- Chạy kiểm tra R1 có fixture marker thật trong bản sao tạm, mở executable JAR sau build.
- Chứng minh external local profile được đọc mà không đóng gói file vào JAR.
- Khởi động local và kiểm tra health/envelope/trace sau sửa; dừng process của chính lượt kiểm tra.
- Kiểm tra file/diff/Git status; không in secret. Nếu dùng skip-tests chỉ cho packaging probe riêng, ghi rõ phạm vi; không gọi đó là full verification.
- Nếu bước nào không chạy được, báo đúng hạn chế và không tự đánh dấu PASS.
