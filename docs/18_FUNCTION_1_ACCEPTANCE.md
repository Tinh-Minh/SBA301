## Contract and packaged-app checks

- [OpenAPI 3.1 contract](api/openapi-function1.json): 32 operations, all local `$ref`s resolve, operation IDs are unique, and method/path inventory matches actual `RequestMappingHandlerMapping` entries. Test compares consumes/bodyless/security semantics and representative response fields/binary headers.
- `Function1OpenApiContractTest` resolves local refs throughout paths and components; compares request allowlists with actual DTO/parser fields, enum values with Java enums/query parsers, and response property/required names with record components. A small regression validator exercises its declared JSON Schema subset and fails if a tested schema introduces an unsupported validation keyword. It ignores formats/annotations and is not a full semantic OpenAPI validator.
- HTTP/PostgreSQL regression covers invalid query enums, profile null/length, required customer/driver reasons, DRIVER_LICENSE submission class, PASSPORT minimal PENDING, voucher numeric bounds/integrality and lexical quota tokens. It also records current duplicate JSON behavior: identical duplicate email keys at login return 200; the guarded voucher command rejects a duplicate code field with 400 and no row mutation.
- Standard production executable JAR was launched with `java -jar` from a Unicode-and-space working directory, using an external profile, external RSA keys and external private storage. Health/register/login/me/private upload/download/owner denial/voucher numeric checks used an isolated PostgreSQL 15.13 Testcontainer.
- The P10-FIX-01 final verification counts and packaging result are recorded in [fix report](reports/P10_FIX_01_REPORT.md); do not infer this repair run's counts from the historical P10 run above.
